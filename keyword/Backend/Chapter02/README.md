## 키워드 정리

- 1. 요구사항 → SQL로 번역하기
    
    찾아보기: 화면 요구사항을 SELECT 컬럼, FROM 테이블, JOIN 관계, WHERE 조건, ORDER BY/LIMIT으로 나누는 방법을 정리해 보세요.
    
    1. 1주차 기준 ERD에서 필요한 테이블과 PK/FK 관계에 표시합니다.
    2. 화면에 보여 줄 컬럼을 SELECT에 먼저 적습니다.
    3. 기준 테이블을 FROM에 적고, ERD의 관계를 따라 필요한 JOIN만 연결합니다.
    4. 현재 사용자, 카테고리, 대여 가능 상태처럼 결과를 좁히는 조건을 WHERE에 적습니다.
    5. 목록이면 ORDER BY와 LIMIT을 마지막에 추가합니다.
    6. 제공된 더미 데이터에서 실행한 결과가 요구사항 문장과 같은지 확인합니다.
- 2. DDL과 DML
    
    찾아보기: CREATE TABLE이 테이블 구조를, INSERT가 행 데이터를 담당하는 이유와 ALTER TABLE과의 차이를 살펴보세요.
    
    DDL (Data Definition Language)
    
    - CREATE, ALTER, DROP, TRUNCATE
    - 역할: 컬럼 이름, 자료형, 제약조건을 설계한다.
    
    DML (Data Manipulation Language)
    
    - SELECT, INSERT, UPDATE, DELETE
    - 구조는 건드리지 않고, 안의 내용물만 넣거나 조회, 수정, 삭제한다.
    
    ---
    
    - CREATE TABLE : 건물을 짓기 위한 빈 설계도를 바탕으로 방 구조(테이블 컬럼)를 처음 만듭니다.
    - INSERT INTO : 이미 완성된 방 안에 사람이나 가구(실제 데이터 행)를 들여보냅니다.
    - ALTER TABLE : 이미 지어진 집(테이블)의 **구조를 리모델링**합니다. (예: 운영 중 새로운 컬럼 추가, 데이터 타입 변경, 인덱스 추가 등). 테이블을 삭제(`DROP`)하지 않고 기존 데이터를 보존하면서 스키마를 바꿀 때 사용합니다.
    
    ```sql
    CREATE TABLE book (
        book_id BIGINT PRIMARY KEY AUTO_INCREMENT,
        title VARCHAR(100) NOT NULL,
        price INT NOT NULL
    );
    ---------------------------------------------------------
    INSERT INTO book (title, price) 
    VALUES 
        ('달빛 도서관', 15000),
        ('우주를 읽는 법', 18000);
    ---------------------------------------------------------
    ALTER TABLE book 
    ADD COLUMN published_date DATE NULL;
    ```
    
- 3. PK·FK와 JOIN 조건
    
    찾아보기: PK·FK가 무엇을 보장하는지, ON 절에서 관계가 잘못 연결되면 왜 중복 행이 생기는지 확인해 보세요.
    
    - PK : 테이블 내 모든 행을 유일하게 식별할 수 있는 유일성(Uniqueness)과 NOT NULL을 보장한다.
    - FK : 다른 테이블의 기본키를 참조함으로써 참조 무결성을 보장. 존재하지 않는 카테고리 ID나 존재하지 않는 유저 ID를 책/대여 테이블에 넣을 수 없도록 막아준다.
    - JOIN : 두 테이블의 모든 행을 짝짓는 데카르트 곱을 기반으로 한다.
    - ON 절은 그 조합 중 어떤 행끼리 짝을 맺을 것인가 필터링하는 연결고리로, 
    만약 ON 조건을 누락하거나 잘못 지정하면 한 쪽 테이블의 1개 행이 상대 테이블의 많은 행과 전부 1:1로 매칭되어 데이터가 중복 생성될 수 있다.
- 4. WHERE와 NULL
    
    찾아보기: WHERE 조건에서 NULL을 = 과 비교할 수 없는 이유와 IS NULL을 사용하는 이유를 알아보세요.
    
    - SQL에서 NULL은 숫자 0이나 빈 문자열(””)이 아닌 알 수 없음(Unknown),값이 정해지지 않음 을 뜻함
    - SQL에서 알 수 없는 값과 알 수 없는 값은 서로 같은지 다른지 판별할 수 없어 UNKNOWN이 된다.
    - WHERE 절은 조건이 TRUE인 행만 통과시키므로, UNKNOWN으로 판정된 행은 결과에서 제외된다.
    - IS NULL / IS NOT NULL : 값이 채워져 있는지 여부를 묻기(= 상태를 묻는) 위해 SQL 표준으로 제공되는 키워드이다.
    - 명확하게 TRUE 또는 FALSE를 반환한다.
- 5. ORDER BY와 일관된 정렬
    
    찾아보기: ORDER BY가 없을 때 목록 순서가 보장되지 않는 이유와 동일 값일 때의 보조 정렬 기준을 찾아보세요.
    
    - RDBMS의 테이블은 수학적 개념인 집합(Set)에 기반합니다. 집합에는 본래 순서가 없습니다.
    - 보조 정렬 기준 : 정렬 기준 뒤 고유 식별자인 PK를 2차/보조 정렬 기준으로 추가한다.
    
    ```sql
    ORDER BY rented_at DESC, rental_id DESC;
    ```
    
- 6. LIMIT / OFFSET과 페이지네이션
    
    찾아보기: LIMIT/OFFSET이 페이지 번호 방식과 어떻게 연결되는지, 데이터가 많아질 때 어떤 한계가 있는지 살펴보세요.
    
    - 페이지네이션(Pagination)은 **수천, 수만 건의 대량 데이터를 한 번에 화면에 불러오지 않고, 일정한 단위(예: 10개씩)로 쪼개서 가져오는 기법**입니다.
    - 1페이지 : LIMIT 10 OFFSET 0 (0개 건너뛰고 10개)
    - 2페이지 : LIMIT 10 OFFSET 0 (10개 건너뛰고 10개)
    - 3페이지 : LIMIT 10 OFFSET 0 (20개 건너뛰고 10개)
    - 스캔 및 버림 비용 : 데이터가 많아지면 (OFFSET 1000000 LIMIT 10) DB는 처음부터 1,000,010 개의 행을 전부 읽은 뒤 앞의 100만개를 버린다. 뒤로 갈수록 쿼리 속도가 느려진다.
    - 데이터 일관성 왜곡 : 1페이지를 보고 있는 사이 새로운 글이 INSERT 되면, 2페이지로 넘어갔을 때 1페이지 끝의 데이터가 다시 나타나는 중복 조회 문제가 발생한다.
    - 대안으로 마지막으로 본 글의 ID를 조건문으로 거는 커서 기반 페이지네이션이 존재
