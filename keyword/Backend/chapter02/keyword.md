# 요구사항 → SQL로 번역하기

## 찾아보기
화면 요구사항을 SELECT 컬럼, FROM 테이블, JOIN 관계, WHERE 조건, ORDER BY/LIMIT으로 나누는 방법을 정리해 보세요.

* 무엇을 보여줄지, 어떤 것을 보여줄지, 어떤 순서로 몇 개 보여줄지를 각각 **SELECT, WHERE, ORDER BY / LIMIT**에 나눠 담은 후 그 사이를 **FROM과 JOIN**이 연결한다.
* 가장 먼저 같은 표의 한 줄이 무엇 하나를 뜻하는가를 정한다. 이 단위에 해당하는 테이블이 **FROM**에 오는 기준 테이블이 된다. 조건과 정렬에 쓰이는 핵심 컬럼을 찾고 같은 대상이 결과에 여러 번 나올 수 있다면 그 반복의 원인이 되는 테이블이 기준이다.
* 결과 항목을 **SELECT 컬럼**으로 옮긴다. 요구사항의 결과에 포함할 항목을 하나씩 적고 각 항목이 어느 테이블의 어느 컬럼인지 짝을 짓는다.
* 필요한 컬럼이 기준 테이블에 없으면 **JOIN**으로 가져온다. 짝지은 컬럼 중 기준 테이블이 밖에 있는 것이 JOIN 대상이다. JOIN의 종류는 짝이 없을 때 기준 행을 남길 것인가로 정한다.
  * **JOIN(INNER):** 짝이 반드시 있거나, 짝이 없는 행은 결과에서 빠짐
  * **LEFT JOIN:** 짝이 없어도 기준 행이 보임
  * **EXISTS / NOT EXISTS:** 상대 테이블의 컬럼을 보여 줄 필요 없이 존재하는지만 알면 될 때 사용
* 요구사항 문장에서 대상을 좁히는 말이 **WHERE 조건**이 된다.
* 순서와 개수를 **ORDER BY / LIMIT**으로 옮긴다.

# DDL과 DML

## 찾아보기
CREATE TABLE이 테이블 구조를, INSERT가 행 데이터를 담당하는 이유와 ALTER TABLE과의 차이를 살펴보세요.

* DDL은 테이블이라는 틀을 정의하고 DML은 그 틀에 담기는 행을 다룬다.
* **CREATE TABLE**은 컬럼 이름, 타입같은 규칙을 정해 데이터가 들어올 수 있는지 확인하는 제약을 정한다. **INSERT**는 그 규칙에 맞는 실제 행을 넣는다. 이렇게 구조와 데이터를 분리하는 이유는 구조는 한 번 정해지면 드물게 바뀌고 모든 행에 영향을 주지만 데이터는 계속 추가, 수정, 삭제되기 때문이다.
* **ALTER TABLE**은 이미 존재하는 테이블의 구조를 바꾸는 DDL이다. 컬럼 추가, 타입 변경, 제약 추가, 삭제 등을 하며 기존 행을 유지한 채 틀만 고친다. **UPDATE**는 데이터를 바꾸지만 **ALTER**는 컬럼 자체를 바꾼다.

# PK·FK와 JOIN 조건

## 찾아보기
PK·FK가 무엇을 보장하는지, ON 절에서 관계가 잘못 연결되면 왜 중복 행이 생기는지 확인해 보세요.

* 기본키는 테이블 안에서 각 행을 유일하게 식별하도록 보장한다. 값이 중복될 수 없고 NULL도 허용되지 않는다. 외래키는 다른 테이블의 PK를 참조하여 두 테이블 사이에 관계를 만들어준다. 
* JOIN을 사용할 때에는 **ON 절** 뒤에 `A.PK = B.FK` 형태의 연결 조건을 반드시 작성해야 한다. 이렇게 하여 테이블의 외래키와 기본키 값이 같은 행끼리 서로 짝을 맞춰 합친다. (FK = 참조 대상의 PK)
* JOIN은 ON 조건이 참인 모든 조합을 결과로 만들기 때문에 의미가 다른 컬럼을 짝지으면 한 행에 여러 행이 달라붙어 결과가 중복되어 출력된다.

# WHERE와 NULL

## 찾아보기
WHERE 조건에서 NULL을 `=`과 비교할 수 없는 이유와 `IS NULL`을 사용하는 이유를 알아보세요.

* NULL은 빈 문자열이 아니라 값이 없음이나 알 수 없음을 뜻한다. 그래서 SQL은 NULL이 비교에 참이나 거짓 대신 **UNKNOWN**을 돌려준다. 
* 따라서 WHERE은 조건이 참인 행만 남기므로 `= NULL`로 쓰면 항상 결과가 나오지 않는다.
* **`IS NULL`**은 이 칸이 비어 있는 상태인가를 검사하고 항상 참이나 거짓을 돌려준다.

# ORDER BY와 일관된 정렬

## 찾아보기
ORDER BY가 없을 때 목록 순서가 보장되지 않는 이유와 동일 값일 때의 보조 정렬 기준을 찾아보세요.

* 관계형 데이터베이스에서 테이블은 순서가 없는 행의 집합으로 취급된다. 따라서 ORDER BY가 없으면 결과 순서는 DB가 그때 고른 실행 방식에 따라 결정된다.
* 값이 같을 경우 순서를 다시 구분하는 두 번째 기준을 붙이는데 이것이 **보조 정렬 기준**이다. 절대 겹치지 않는 값이어야 하므로 보통 행마다 고유한 번호인 PK를 사용한다.

# LIMIT / OFFSET과 페이지네이션

## 찾아보기
LIMIT/OFFSET이 페이지 번호 방식과 어떻게 연결되는지, 데이터가 많아질 때 어떤 한계가 있는지 살펴보세요.

* LIMIT과 OFFSET은 조회 결과의 개수와 시작 위치를 제한할 때 사용한다. LIMIT은 가져올 행의 수, OFFSET은 앞에서 건너뛸 행의 수다.
* OFFSET은 건너뛸 행을 실제로 읽은 뒤 버리는 방식이다. 따라서 뒤 페이지로 갈수록 느려진다. 
* 또한 데이터 변경 시 요청 때 모든 행이 한 칸 씩 밀려 마지막 항목이 다시 나오는 중복이 일어나거나 삭제가 일어나면 반대로 한 항목을 건너뛰는 누락이 발생할 수 있다.
