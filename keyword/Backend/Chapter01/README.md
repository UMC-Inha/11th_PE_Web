# Backend Chapter01

## 키워드 정리

- PK, FK란?
    
    PK(Primary Key)
    
    - 테이블에서 각 행을 유일하게 식별할 수 있는 대표 식별자
    - 중복된 값을 가질 수 없고(Unique), 빈 값을 허용하지 않음(NOT NULL)
    - 테이블 당 하나의 기본키만 지정(2개 이상의 컬럼을 묶은 복합키도 가능!)
    
    FK(Foreign Key)
    
    - 다른 테이블의 기본키(PK) 또는 UNIQUE 제약이 걸린 후보키를 참조하는 컬럼
    - 자기 자신을 참조하는 경우도 있으며, DBMS에 따라 다른 테이블의 PK뿐 아니라 UNIQUE 제약이 걸린 컬럼도 참조할 수 있음
    - 테이블 간의 관계를 맺어주고, FK 값이 NULL이 아닌 경우에는 참조하는 테이블에 실제 존재하는 값만 입력 받도록 참조 무결성을 보장함
    - FK 컬럼이 NULL을 허용하면 참조 행 없이 NULL을 저장할 수 있으므로, 참조 무결성은 보통 NULL이 아닌 값에 대해 적용됨

- ERD란?
    
    ERD(Entity Relationship Diagram)
    
    - 데이터베이스의 구조와 테이블 간의 관계를 시각적으로 표현한 개체-관계 모델 다이어그램
    - 요구사항 분석 단계 이후 데이터 모델링 시 설계도 형태로 정리하여 데이터 구조의 무결성과 확장성을 점검하는 데 사용됨

- 연관관계란? 그리고 연관관계를 설정하는 방법은?
    
    연관관계
    
    - 두 개 이상의 테이블이 서로 어떻게 연결되어 있는지를 나타내는 관계
    - 1:1, 1:N, N:M
    - 관계를 구현하는 방법:
        - 1:N: N쪽 테이블에 FK를 두어 연결
        - 1:1: 한쪽 테이블에 FK를 두고, 해당 컬럼에 UNIQUE 제약을 적용
        - N:M: 연결 테이블을 만들고 각 테이블의 PK를 FK로 저장
        - 필수 관계라면 FK 컬럼에 NOT NULL을 적용하여 반드시 값이 있어야 함

- 정규화란?
    
    정규화(Normalization)
    
    - 데이터 중복을 줄이고, 삽입·수정·삭제 이상(anomaly)을 방지해 데이터의 무결성과 유지보수성을 높이는 과정
    - 중복을 완전히 없애는 것이 아니라, 중복을 최소화하고 이상 현상을 줄이는 것이 목적
    - 제 1 정규화: 테이블의 컬럼이 원자값을 갖도록 분해하는 것
    - 제 2 정규화: 제 1 정규화를 진행한 테이블에 대해 부분 함수 종속을 제거하고 완전 함수 종속을 만족하도록 분해하는 것
        - 완전 함수 종속: 기본키의 전체 집합이 결정자가 되어야 하며, 기본키의 일부만으로 다른 속성이 결정되어서는 안 됨
        - 복합 키를 사용할 때 특히 중요하며, 단일 컬럼 기본키를 가진 테이블은 보통 자동으로 만족함
    - 제 3 정규화: 제 2 정규화를 진행한 테이블에 대해 비키 속성 간의 이행적 종속을 제거하도록 분해하는 것
        - 예: A → B, B → C일 때 A → C가 성립하면 비키 속성 간의 이행적 종속이 발생한다고 봄

- 반 정규화란?
    
    반정규화
    
    - 성능 향상을 위해 일부 데이터 중복이나 계산 결과를 허용하고 조인을 줄이는 설계 기법
    - 조회 속도는 향상되지만 데이터 일관성 유지와 모델의 유연성이 상대적으로 낮아질 수 있음
    - 계산된 컬럼 추가: 자주 조회되는 값을 미리 계산해 저장
    - 테이블 병합: 자주 함께 조회되는 테이블을 합쳐 조회 비용을 줄임
    - 반정규화와 분할 개념을 구분하면:
        - 테이블 수직 분할: 하나의 테이블을 여러 테이블로 나누는 설계
        - 테이블 수평 분할: 하나의 테이블을 값 기준으로 여러 파티션으로 나누는 방식
        - 위 두 방식은 일반적으로 반정규화라기보다 파티셔닝 또는 물리적 설계 기법에 가깝다

- DB에서의 상속 관계 표현은 어떻게 하는가?
    
    일반 데이터베이스에는 객체 상속 개념이 없고, 보통 ORM(특히 JPA)에서 설명하는 Super-Type Sub-Type 모델을 세 가지 전략 중 하나로 매핑한다.
    
    - 조인 전략: 슈퍼타입-서브타입 각각 테이블 생성
        - 공통 속성을 가진 슈퍼타입 테이블과 서브타입 테이블을 따로 만들고, 자식의 PK이자 FK로 부모의 PK를 공유하는 구조
        - 정규화가 잘 되어 있으나, 서브타입의 전체 정보를 조회할 때 주로 JOIN이 필요해 쿼리가 복잡해질 수 있음
    - 단일 테이블 전략
        - 자식 클래스의 모든 속성을 부모 테이블에 몰아 넣고, 어떤 타입인지 구분하는 컬럼을 두는 방식
        - JOIN이 필요 없어 조회가 빠르나, 다른 자식의 컬럼들은 NULL을 허용해야 하고 테이블 크기가 비대해짐
    - 구현 클래스마다 테이블 생성
        - 공통 부모 테이블 없이 각 자식마다 필요한 모든 컬럼을 복사해 각각 별개의 테이블로 만드는 방식
        - 자식 테이블을 묶어서 조회할 때 UNION이 필요할 수 있으며, 다형성 조회를 자주 사용하지 않는다면 적합할 수 있음

- 인덱스란?
    
    인덱스(Index)
    
    - 테이블의 데이터 검색 속도를 빠르게 하기 위해 특정 컬럼의 값을 기준으로 정렬된 구조를 유지하는 자료구조로, 일반적으로 B-tree 인덱스에 적용되는 개념이며 해시 인덱스 등 다른 유형은 동작 방식이 다름
    - WHERE, JOIN, ORDER BY 연산의 성능 향상은 인덱스가 적용된 컬럼, 조건식, 선택도(selectivity)에 따라 달라짐
    - INSERT, UPDATE, DELETE 시 인덱스 엔트리를 갱신해야 하고, B-tree 인덱스는 트리 구조를 재구성할 수도 있어 쓰기 비용이 증가할 수 있음
