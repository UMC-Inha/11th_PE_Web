- PK, FK란?

  PK(Primary Key) - 기본키

    - 한 행을 대표하는 식별자
    - NULL값을 가질 수 없음
    - 중복될 수 없음

  FK(Foreign Key) - 외래키

    - 다른 테이블에 있는 PK를 참조
    - 테이블 간 관계를 만든다
    - JOIN의 기준이 되는 경우가 많음
- ERD란?

  ERD - RDB의 테이블간의 관계를 시각화하는 모델링 도구

    - Entity(엔터티) - 데이터베이스에 저장할 실제 대상
    - Attribute(속성) - 엔터티가 가지는 특성, 데이터베이스에서는 컬럼에 해당
    - Relationship(관계) - 엔터티 간의 연관성
    - 1:1, 1:N, N:M
- 연관관계란? 그리고 연관관계를 설정하는 방법은?

  연관관계란?

    - 테이블 간에 FK로 맺어지는 관계

  관계의 종류

    - 1:1(일대일 관계) - 한 회원이 하나의 소셜 로그인 계정과 연결되는 경우
    - 1:N(일대다 관계) - 책이 하나의 카테고리를 가지고 한 카테고리에 여러 책이 속하는 경우
    - N:M(다대다 관계) - 사용자가 책 여러권을 대여할 수 있고 한 책도 여러 사용자가 대여할 수 있는 경우

  설정 방법

    1. 어떤 관계인지 판단한다
       두 엔터티가 어떤 관계 종류를 가지는지 생각한다
    2. 결정된 관계를 DB에 구현한다

  | 관계 | 구현 |
      | --- | --- |
  | 1:1 | 다른 테이블의 PK를 FK로 설정 |
  | 1:N | N쪽 테이블에 1쪽 PK를 참조하는 FK 설 |
  | N:M | 중간 테이블 생성 → 제 1정규화를 통해 1:N 두 개로 분해 |
- 정규화란?

  정규화란?

    - 데이터의 중복을 없애고 이상현상을 없애는 과정

  제1 정규형(1NF)

    - 각 컬럼이 하나의 속성만을 가져야 한다
    - 하나의 칼럼은 같은 종류나 타입( type)을 가져야한다
    - 각 칼럼이 유일한(unique) 이름을 가져야 한다
    - 칼럼의 순서가 상관이 없어야 한다

  제2 정규형(2NF)

    - 1정규형을 만족해야 한다
    - 모든 칼럼이 부분적 종속이 없어야 한다

  제3 정규형(3NF)

    - 2정규형을 만족해야 한다
    - 기본키를 제외한 속성들 간의 이행 종속성이 없어야 한다
    * 이행종속성 : A→B, B→C일 때 A→C가 성립하는 경우

  정규화의 장점

    - 데이터 중복 제거
    - 저장 공간 절약
    - 데이터 무결성 보장
    - 데이터의 일관성을 유지하고 오류를 방지함
    - 데이터 관리 용이
    - 유지보수가 쉬워짐
    - 이상 현상 제거
    - 비정상적인 문제 해결

  정규화의 단점

    - 성능저하
    - 데이터 조회 시에 조인을 유발하기 때문에 CPU와 메모리를 많이 사용한다
- 반 정규화란?

  반정규화란?

    - 데이터베이스의 성능 향상을 위해, 데이터의 중복을 허용하고 조인을 줄이는 과정

  반정규화를 수행하는 경우

    - 다량의 범위를 자주 처리해야 하는 경우
    - 특정 범위의 데이터만 자주 처리하는 경우
    - 집계 정보가 자주 요구되는 경우

  반정규화의 장점

    - 조회 성능 향상
    - 빠르게 접근 가능
    - 조인 비용 감소
    - 시스템 부담이 줄어든다

  반정규화의 단점

    - 데이터 중복 증가
    - 데이터 무결성이 깨질 위험이 있음
    - 유지보수 어려움
    - 중복 데이터로 인해 변경 작업이 복잡해짐

  주요 반정규화 기법

  | 테이블 합치기 | 자주 조인되는 두 테이블을 하나로 병합 |
      | --- | --- |
  | 중복 칼럼 추가 | 자주 사용되는 데이터를 다른 테이블에 중복 저장 |
  | 파생 칼럼 추가 | 계산된 값을 저장하는 컬럼을 추가 |
  | 수평 분할 | 행을 기준으로 테이블을 분리 |
  | 수직 분할 | 칼럼을 분할하여 테이블 분리 |
- DB에서의 상속 관계 표현은 어떻게 하는가?

  DB에는 객체 관계에서의 상속 개념이 없다. 대신에 Super Type과 Sub Type 이라는 모델링 기법이 유사하다. Super Type, Sub Type 의 논리 모델을 테이블로 나타내는 방법에는 3가지 방법이 있다.

    1. 조인 전략
    - 각각의 객체를 모두 테이블로 만들고, 조회할 때는 조인을 활용

    - 장단점
    - 장점
    - 테이블이 정규화 되고, 저장 공간을 효율적으로 사용 가능
    - 단점
    - 쿼리가 복잡해지고 성능이 저하될 수 있음

    1. 단일 테이블 전략
    - 각각의 객체를 테이블 하나만 사용해서 통합한다

    - 장단점
    - 장점
    - 조인이 없어서 빠르고 조회 커리가 단순해짐
    - 단점
    - 자식이 많아지면 테이블이 커지고 성능이 저하될 수 있음

    1. 구현 클래스마다 테이블 전략
    - 자식 엔터티마다 하나의 테이블을 만든다

    - 장단점
    - 장점
    - 서브 타입을 구분해서 처리할 때 효과적
    - 단점
    - 여러 자식 테이블을 혼합해서 조회할 때 느림
    - 자식 테이블을 통합해서 쿼리하기 어려움

- 인덱스란?

  인덱스란?

    - 데이터베이스에서 특정 컬럼의 값을 빠르게 찾을 수 있도록 만들어진 검색용 구조
    - EX) 도서관에서 책을 찾기 위해 사용하는 “책 번호”와 같은 역할

  장단점

    - 장점
    - 데이터 검색 속도 향상
    - 중복 방지
    - 데이터 정렬이 효율적
    - 단점
    - 저장공간 차지
    - 삽입, 업데이트, 삭제 성능 저하
