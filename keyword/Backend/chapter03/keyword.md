- SQL Injection을 포함한 대표적인 웹 보안 공격 기법
  SQL Injection : 사용자 입력값이 SQL 코드의 일부로 해석되어 발생하는 문제이다.
  예를 들어 사용자가 id 입력칸에 ‘1’=’1 — 을 입력하면 1=1은 항상 참이고 — 뒤는 주석처리되어 비밀번호 검사가 사라지게 된다.
  SQL Injection 방어 방법은 파라미터 바인딩에 있다. 파라미터 바인딩이란 외부에서 들어온 값을 프로그램의 함수 파라미터에 자동으로 연결시켜 주는 것이다.쿼리 구조를 먼저 DB에 보낸 뒤 입력값은 나중에 순수한 데이터로만 끼워 넣는다. 이렇게 하면 SQL과 데이터를 분리하여서 사용자가 쿼리 문을 입력하더라도 단순한 문자열 데이터로 처리되게 된다.
  -대표적인 웹 보안 공격 기법-
  | 공격                               | 원리                                                                                      | 주요 방어책                                                            |
  | ---------------------------------- | ----------------------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
  | XSS (Cross-Site Scripting)         | 게시글 등에 악성 스크립트를 심어 다른 사용자의 브라우저에서 실행시킴. 쿠키 탈취 등에 쓰임 | 출력 시 HTML 이스케이프, CSP 헤더, 쿠키에 HttpOnly 설정                |
  | CSRF (Cross-Site Request Forgery)  | 로그인된 사용자가 악성 페이지를 열면, 사용자 몰래 송금·비밀번호 변경 등의 요청이 전송됨   | CSRF 토큰, 쿠키 SameSite 속성, 중요 작업 시 재인증                     |
  | 커맨드 인젝션                      | 입력값이 서버의 OS 명령어로 실행됨 (`ping 입력값; rm -rf /`)                              | 쉘 호출 자체를 피하고, 불가피하면 화이트리스트 검증                    |
  | 경로 조작 (Path Traversal)         | `../../etc/passwd`처럼 상위 경로로 이동해 허용되지 않은 파일에 접근                       | 경로 정규화 후 허용 디렉터리 안인지 검사                               |
  | SSRF (Server-Side Request Forgery) | 서버가 공격자가 지정한 URL로 요청을 보내게 만들어 내부망에 접근                           | 요청 대상 도메인·IP 화이트리스트, 내부 IP 대역 차단                    |
  | IDOR / 접근 제어 실패              | `/orders/1001`을 `/orders/1002`로 바꿔 남의 데이터를 조회                                 | 모든 요청에서 서버 측 권한 검사                                        |
  | 세션 하이재킹                      | 탈취한 세션 ID로 다른 사용자 행세                                                         | HTTPS 강제, 로그인 시 세션 ID 재발급, 쿠키 Secure 설정                 |
  | 파일 업로드 취약점                 | 웹셸 같은 실행 파일을 업로드해 서버에서 실행                                              | 확장자·MIME 검증, 업로드 경로를 실행 불가 영역으로 분리, 파일명 난수화 |
  | 클릭재킹                           | 투명한 iframe을 덮어 사용자가 의도치 않은 버튼을 누르게 함                                | X-Frame-Options 또는 CSP frame-ancestors 헤더                          |
  이 목록들을 발생시키는 두 가지 핵심 문제는 신뢰할 수 없는 입력이 코드로 해석되는 문제, 서버가 요청의 주체나 권한은 제데로 확인하지 않는 문제이다.
- 커넥션 풀(Connection Pool)이란?
  API를 호출할 때마다 서버가 MySQL의 문을 매번 두드리고 비밀번호를 확인하며 연결을 맺는다면, 서버는 연결을 맺고 끊는 데에만 대부분의 시간을 낭비하게된다. 또한 DB연결을 하나 새로 만드는 데는 많은 비용이 들고 한 번에 수십 ms가 걸리기도 한다. 그러면 실제 쿼리보다 연결 작업에 시간이 더 드는 상황이 생긴다.
  커넥션 풀은 애플리케이션 시작 시 일정 수의 DB 연결을 미리 만들어 두고, 요청이 오면 빌려주고 끝나면 돌려받아 재사용하는 방식이다.
  **동작 흐름**
  1. 애플리케이션 시작 시 설정된 수만큼 커넥션을 생성해 풀에 보관합니다.
  2. 요청이 들어오면 풀에서 유휴 커넥션 하나를 빌려 씁니다.
  3. 작업이 끝나 `close()`를 호출하면, 실제로 연결을 끊지 않고 풀에 반납합니다.
  4. 남은 커넥션이 없으면 다른 요청이 반납할 때까지 대기하고, 제한 시간을 넘기면 예외가 발생합니다.
  이 때 풀 크기는 클수록 좋은 것은 아니다. DB 서버에 CPU 코어 수는 한정되어있어 동시에 실행할 수 있는 쿼리 수에도 한계가 있다. 커넥션이 지나치게 많으면 DB 내부에서 컨텍스트 스위칭(**실행 중인 스레드/프로세스를 CPU가 다른 스레드/프로세스로 바꾸는 것)**과 락 경합(여러 스레드가 **같은 락을 얻으려고 경쟁하는 상황)** 만 늘게 되어 오히려 처리량이 떨어진다.
  -커넥션 풀 관련 장애-
  - **커넥션 누수:** 예외 발생 시 커넥션을 반납하지 않아 풀이 점점 말라 갑니다. Java라면 try-with-resources로 반납을 보장해야 합니다.
  - **풀 데드락:** 한 요청이 커넥션 하나를 쥔 채 두 번째 커넥션을 요청하는 구조에서는, 동시 요청이 몰리면 모두가 서로를 기다리며 멈춥니다.
  - **트랜잭션 안의 외부 호출:** 트랜잭션 내부에서 외부 API를 호출하면 응답을 기다리는 동안 커넥션이 묶여, 정작 DB 작업은 하지 않는데 풀이 고갈됩니다.
- Raw SQL vs ORM
  Raw SQL은 개발자가 SQL을 직접 작성해 실행하는 방식이고, ORM(Object-Relational Mapping)은 객체와 테이블을 매핑해 두고 객체를 다루면 프레임워크가 SQL을 만들어 주는 방식이다.
  | 기준        | Raw SQL                                 | ORM                                               |
  | ----------- | --------------------------------------- | ------------------------------------------------- |
  | 생산성      | 반복 코드(매핑, 연결 처리)가 많음       | 단순 CRUD는 매우 빠르게 작성                      |
  | 성능 제어   | 실행되는 쿼리를 정확히 통제             | 생성되는 쿼리를 확인하지 않으면 비효율 발생       |
  | 복잡한 쿼리 | 통계, 다중 조인, 윈도우 함수 등에 강함  | 표현이 어렵거나 오히려 장황해짐                   |
  | DB 종속성   | 특정 DB 문법에 묶이기 쉬움              | DB 교체가 비교적 쉬움                             |
  | 유지보수    | 테이블 변경 시 문자열 SQL을 일일이 수정 | 엔티티 수정으로 상당 부분 반영                    |
  | 학습 곡선   | SQL만 알면 됨                           | 영속성 컨텍스트, 지연 로딩 등 별도 개념 학습 필요 |
  | 보안        | 바인딩을 빼먹으면 인젝션에 취약         | 기본적으로 파라미터 바인딩 사용                   |
  단순 CRUD와 도메인 로직은 ORM으로 처리하고, 복잡한 조회나 통계·대량 처리는 쿼리 빌더나 네이티브 쿼리로 처리하는것이 좋다.
- INSERT 외에 데이터를 다루는 핵심 SQL 문법
  용도에 따라 네 가지로 나뉜다. 데이터 다루기(DML), 테이블 구조 정의(DDL), 권한 관리(DCL), 트랜잭션 제어(TCL)
  | 분류     | 문법                                    | 용도                                    | 예시                                                                 |
  | -------- | --------------------------------------- | --------------------------------------- | -------------------------------------------------------------------- |
  | 조회     | `SELECT`                                | 데이터 조회                             | `SELECT id, name FROM users;`                                        |
  | 조회     | `WHERE`                                 | 행 조건 필터링                          | `SELECT * FROM users WHERE age >= 20;`                               |
  | 조회     | `IN` / `BETWEEN` / `LIKE`               | 목록·범위·패턴 조건                     | `WHERE city IN ('Seoul', 'Busan')`                                   |
  | 조회     | `IS NULL`                               | NULL 비교 (`=` 사용 불가)               | `WHERE email IS NULL`                                                |
  | 조회     | `ORDER BY`                              | 정렬 (ASC 오름차순, DESC 내림차순)      | `ORDER BY created_at DESC`                                           |
  | 조회     | `LIMIT` / `OFFSET`                      | 개수 제한, 페이징                       | `LIMIT 10 OFFSET 20`                                                 |
  | 조회     | `DISTINCT`                              | 중복 제거                               | `SELECT DISTINCT city FROM users;`                                   |
  | 집계     | `COUNT` / `SUM` / `AVG` / `MAX` / `MIN` | 집계 계산                               | `SELECT COUNT(*) FROM users;`                                        |
  | 집계     | `GROUP BY`                              | 그룹별 집계                             | `SELECT city, COUNT(*) FROM users GROUP BY city;`                    |
  | 집계     | `HAVING`                                | 집계 결과 필터링                        | `GROUP BY city HAVING COUNT(*) >= 100`                               |
  | 연결     | `INNER JOIN`                            | 양쪽 모두 일치하는 행만                 | `FROM users u JOIN orders o ON u.id = o.user_id`                     |
  | 연결     | `LEFT JOIN`                             | 왼쪽 전부 + 오른쪽 일치분 (없으면 NULL) | `FROM users u LEFT JOIN orders o ON u.id = o.user_id`                |
  | 연결     | 서브쿼리                                | 쿼리 안의 쿼리                          | `WHERE age > (SELECT AVG(age) FROM users)`                           |
  | 연결     | `EXISTS`                                | 관련 행 존재 여부 확인                  | `WHERE EXISTS (SELECT 1 FROM orders o WHERE o.user_id = u.id)`       |
  | 변경     | `INSERT`                                | 데이터 삽입                             | `INSERT INTO users (name, age) VALUES ('홍길동', 25);`               |
  | 변경     | `UPDATE`                                | 데이터 수정 (WHERE 필수)                | `UPDATE users SET city = 'Busan' WHERE id = 1;`                      |
  | 변경     | `DELETE`                                | 데이터 삭제 (WHERE 필수)                | `DELETE FROM users WHERE id = 1;`                                    |
  | 변경     | UPSERT                                  | 있으면 수정, 없으면 삽입                | MySQL `ON DUPLICATE KEY UPDATE` / PostgreSQL `ON CONFLICT DO UPDATE` |
  | 트랜잭션 | `BEGIN` / `COMMIT` / `ROLLBACK`         | 작업 묶음의 확정·취소                   | `BEGIN; UPDATE ...; UPDATE ...; COMMIT;`                             |
  | 구조     | `CREATE TABLE`                          | 테이블 생성                             | `CREATE TABLE users (id BIGINT PRIMARY KEY, name VARCHAR(50));`      |
  | 구조     | `ALTER TABLE`                           | 컬럼 추가·삭제·변경                     | `ALTER TABLE users ADD COLUMN phone VARCHAR(20);`                    |
  | 구조     | `CREATE INDEX`                          | 인덱스 생성 (조회 속도 향상)            | `CREATE INDEX idx_city ON users(city);`                              |
  | 구조     | `TRUNCATE`                              | 구조는 두고 데이터만 전부 삭제          | `TRUNCATE TABLE logs;`                                               |
  | 구조     | `DROP TABLE`                            | 테이블 자체 삭제                        | `DROP TABLE logs;`                                                   |
  | 권한     | `GRANT` / `REVOKE`                      | 권한 부여·회수                          | `GRANT SELECT ON users TO 'reader';`                                 |
