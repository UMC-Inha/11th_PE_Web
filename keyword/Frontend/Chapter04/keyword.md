- Web Storage
    - localStorage와 sessionStorage는 저장값의 수명과 공유 범위가 어떻게 다른가요?
        
        ## localStorage와 sessionStorage의 차이
        
        `localStorage`와 `sessionStorage`는 모두 같은 origin에서 데이터를 문자열 형태로 저장하는 브라우저 저장소다. 두 저장소의 가장 큰 차이는 **저장값의 수명과 탭 사이의 공유 여부**다.
        
        | 구분 | `localStorage` | `sessionStorage` |
        | --- | --- | --- |
        | 저장값 수명 | 직접 삭제하기 전까지 유지 | 해당 탭을 닫을 때 삭제 |
        | 새로고침 | 유지됨 | 유지됨 |
        | 브라우저 재실행 | 유지됨 | 삭제됨 |
        | 같은 origin의 다른 탭 | 공유됨 | 공유되지 않음 |
        | 적합한 데이터 | 다음 방문에도 유지할 설정·북마크 | 현재 탭에서만 필요한 임시 상태 |
        
        `localStorage`는 브라우저를 닫았다가 다시 열어도 값이 유지된다. 또한 protocol, host, port가 같은 origin의 탭들은 동일한 저장소를 사용하므로 북마크나 테마 설정처럼 다음 방문에도 유지할 값에 적합하다.
        
        `sessionStorage`는 현재 탭의 세션이 유지되는 동안만 값을 보관한다. 새로고침해도 값은 유지되지만 탭을 닫으면 삭제되며, 같은 주소를 다른 탭에서 열어도 저장값을 기본적으로 공유하지 않는다.
        
        두 저장소 모두 사용자가 개발자 도구에서 값을 수정하거나 삭제할 수 있으므로 저장값을 항상 신뢰해서는 안 된다. 비밀번호, 개인정보처럼 민감한 데이터도 저장하지 않는 것이 좋다.
        
    - 객체나 배열을 저장할 때 JSON 문자열로 바꿔야 하는 이유는 무엇일까요?
        
        ## 객체나 배열을 저장할 때 JSON 문자열로 바꿔야 하는 이유
        
        `localStorage`와 `sessionStorage`는 **문자열 형태의 값만 저장할 수 있기 때문**이다.
        
        객체나 배열을 그대로 저장하면 객체의 내부 데이터가 정상적으로 저장되지 않는다.
        
        ```tsx
        const movieIds = [2, 7];
        
        localStorage.setItem("bookmarks", movieIds);
        ```
        
        `setItem()`은 전달받은 값을 문자열로 변환하므로 의도한 배열 형태가 유지되지 않는다. 특히 객체를 그대로 저장하면 다음과 같이 저장된다.
        
        ```tsx
        const movie = {
          id: 1,
          title: "인셉션",
        };
        
        localStorage.setItem("movie", movie);
        
        // 저장되는 값
        "[object Object]"
        ```
        
        따라서 `JSON.stringify()`를 사용해 객체나 배열의 구조를 유지하는 JSON 문자열로 변환해야 한다.
        
        ```tsx
        const movieIds = [2, 7];
        
        localStorage.setItem(
          "bookmarks",
          JSON.stringify(movieIds),
        );
        ```
        
        저장된 값을 사용할 때는 문자열이므로 `JSON.parse()`를 사용해 다시 JavaScript 객체나 배열로 변환한다.
        
        ```tsx
        const storedValue = localStorage.getItem("bookmarks");
        
        const movieIds = storedValue
          ? JSON.parse(storedValue)
          : [];
        ```
        
        정리하면 다음과 같다.
        
        ```
        객체 또는 배열
        → JSON.stringify()
        → JSON 문자열로 저장
        → JSON.parse()
        → 객체 또는 배열로 복원
        ```
        
        단, `JSON.parse()`는 저장된 문자열이 올바른 JSON 형식이 아니면 오류가 발생한다. 따라서 실제 코드에서는 `try-catch`와 기본값을 사용해 잘못된 저장값을 처리하는 것이 좋다.
        
    - Web Storage에는 어떤 데이터를 저장하는 것이 적절할까요?
        
        Web Storage에는 **용량이 작고, 브라우저에서 관리해도 되며, 사용자가 수정하거나 삭제해도 문제가 없는 데이터**를 저장하는 것이 적절하다.
        
        대표적인 예시는 다음과 같다.
        
        - 북마크한 영화 ID 목록
        - 다크 모드와 같은 화면 설정
        - 언어 설정
        - 최근 검색어
        - 임시로 작성 중인 폼 내용
        - 현재 선택한 필터나 정렬 기준
        - 다시 표시하지 않을 안내창 여부
        
        다음과 같은 데이터는 저장하지 않는 것이 좋다.
        
        - 비밀번호
        - 주민등록번호나 결제 정보 같은 개인정보
        - 서버가 원본인 대규모 데이터
        - 조작되면 권한이나 금액이 바뀌는 중요한 데이터
        - 자주 변경되는 대용량 데이터
        - 민감한 인증 정보
        
        Web Storage의 값은 사용자가 개발자 도구에서 직접 확인하거나 수정하고 삭제할 수 있다. 따라서 저장된 값을 항상 올바르다고 믿어서는 안 되며, 값을 읽을 때 형식 검사와 기본값 처리가 필요하다.
        
        또한 Web Storage는 동기적으로 동작하므로 큰 데이터를 자주 읽고 쓰면 화면 동작을 방해할 수 있다. 정리하면 **보안상 중요하지 않은 소량의 클라이언트 상태**를 저장하는 데 적합하다.
        
- 클라이언트 상태와 전역 상태 관리
    - 컴포넌트 상태와 전역 상태는 사용하는 범위가 어떻게 다른가요?
        
        컴포넌트 상태와 전역 상태는 **상태를 사용하는 컴포넌트의 범위**에서 차이가 있다.
        
        | 구분 | 컴포넌트 상태 | 전역 상태 |
        | --- | --- | --- |
        | 사용 범위 | 특정 컴포넌트와 가까운 자식 | 여러 라우트와 컴포넌트 |
        | 관리 방법 | `useState` | Zustand 등의 전역 store |
        | 대표 예시 | 입력값, 모달 열림 여부 | 북마크 목록, 사용자 설정 |
        | 공유 방식 | 필요하면 props로 전달 | store에서 직접 조회·변경 |
        
        ### 컴포넌트 상태
        
        특정 컴포넌트 또는 가까운 자식 컴포넌트에서만 사용하는 상태다.
        
        ```tsx
        const [isOpen, setIsOpen] = useState(false);
        ```
        
        입력값이나 모달 열림 여부처럼 사용 범위가 좁은 값은 컴포넌트 내부에서 관리하는 것이 좋다.
        
        ### 전역 상태
        
        서로 멀리 떨어진 여러 컴포넌트나 라우트에서 함께 사용하는 상태다.
        
        ```tsx
        const bookmarkedMovieIds = useBookmarkStore(
          (state) => state.bookmarkedMovieIds,
        );
        ```
        
        북마크 목록처럼 여러 화면에서 조회하고 변경해야 하는 값은 Zustand 등의 전역 store로 관리할 수 있다.
        
        모든 상태를 전역으로 관리할 필요는 없다. 한 컴포넌트에서만 사용하는 값은 로컬 상태로 두고, 여러 영역에서 공유해야 하는 값만 전역 상태로 관리하는 것이 좋다.
        
    - 여러 화면에서 사용하는 북마크 상태를 전역으로 관리하면 어떤 장점과 비용이 생길까요?
        
        ### 장점
        
        - 여러 화면에서 동일한 북마크 목록을 사용할 수 있다.
        - 부모 컴포넌트를 거쳐 계속 props를 전달하지 않아도 된다.
        - 한 화면에서 북마크를 변경하면 다른 컴포넌트에도 같은 상태가 반영된다.
        - 북마크 추가·해제 로직을 store의 action으로 모아 중복을 줄일 수 있다.
        - Zustand의 `persist`를 적용하면 새로고침 후에도 북마크를 유지할 수 있다.
        
        ### 비용과 주의점
        
        - Zustand 같은 별도의 상태 관리 도구와 store 구조를 익혀야 한다.
        - 전역 상태와 action이 많아지면 상태가 어디에서 변경됐는지 파악하기 어려워질 수 있다.
        - 필요한 값만 선택하지 않으면 관련 없는 상태 변경에도 컴포넌트가 다시 렌더링될 수 있다.
        - 한두 컴포넌트에서만 사용하는 상태까지 전역으로 관리하면 구조가 불필요하게 복잡해진다.
        - 서버 상태까지 전역 store에 복사하면 서버 데이터와 store 중 어느 값이 최신인지 판단하기 어려워질 수 있다.
        
        따라서 북마크처럼 여러 화면에서 함께 사용하고 변경해야 하는 클라이언트 상태는 전역 관리가 적합하다. 반면 입력값이나 모달 열림 여부처럼 특정 컴포넌트에서만 사용하는 값은 로컬 상태로 관리하는 것이 좋다.
        
    - Zustand와 Web Storage는 북마크 상태를 관리할 때 각각 어떤 역할을 할까요?
        
        
        | 구분 | Zustand | Web Storage |
        | --- | --- | --- |
        | 주요 역할 | React 앱의 상태 관리 | 브라우저에 데이터 저장 |
        | 상태 사용 | 여러 컴포넌트에서 조회·변경 | 문자열 형태로 보관 |
        | 유지 기간 | 기본적으로 새로고침 전까지 | 새로고침 후에도 유지 가능 |
        | 상태 변경 반영 | 변경 시 컴포넌트 다시 렌더링 | 직접 변경해도 React가 자동으로 렌더링하지 않음 |
        | 북마크 예시 | 북마크 목록과 추가·해제 함수 관리 | 북마크 ID 목록 저장 |
        
        ### Zustand의 역할
        
        Zustand는 북마크 ID 목록과 북마크를 추가하거나 해제하는 action을 store에서 관리한다. 여러 화면과 컴포넌트가 같은 북마크 상태를 사용할 수 있고, 상태가 변경되면 이를 사용하는 컴포넌트가 다시 렌더링된다.
        
        ```tsx
        const isBookmarked = useBookmarkStore((state) =>
          state.bookmarkedMovieIds.includes(movieId),
        );
        ```
        
        ### Web Storage의 역할
        
        Web Storage는 북마크 목록을 브라우저에 저장한다. 따라서 페이지를 새로고침하거나 브라우저를 다시 열어도 저장된 북마크를 복원할 수 있다.
        
        ```tsx
        localStorage.setItem(
          "bookmarks",
          JSON.stringify(bookmarkedMovieIds),
        );
        ```
        
        하지만 Web Storage에 값을 저장하는 것만으로는 React 화면이 자동으로 바뀌지 않는다. 저장된 값을 읽어 React 상태에 반영하는 과정이 필요하다.
        
        ### `persist`로 연결하기
        
        Zustand의 `persist` 미들웨어를 사용하면 Zustand 상태를 Web Storage에 자동으로 저장하고 다시 불러올 수 있다.
        
        ```
        Zustand
        → 실행 중 북마크 상태 관리
        → 상태 변경 시 화면 업데이트
        
        Web Storage
        → 북마크 상태 저장
        → 새로고침 후 상태 복원
        ```
        
        즉, **Zustand는 현재 실행 중인 앱의 북마크 상태를 관리하고, Web Storage는 그 상태가 사라지지 않도록 저장하는 역할**을 한다.
