- 프레임워크의 역할
  - Next.js는 TanStack Router에 더해 어떤 기능을 제공하나요?
    - TanStack Router는 주로 React 애플리케이션의 라우팅, URL 상태 관리, 타입 안전성, 데이터 로딩 등을 담당하는 라이브러리이다.
    - Next.js는 라우팅 기능뿐 아니라 서버 렌더링(SSR), 정적 페이지 생성(SSG), 부분적 정적 재생성(ISR) 등 다양한 렌더링 방식을 지원하는 프레임워크이다.
      - 서버 컴포넌트(Server Components)를 통해 서버에서 컴포넌트를 렌더링하고 클라이언트에 전달되는 JavaScript 부담을 줄일 수 있다.
      - 서버 액션(Server Actions)과 Route Handlers를 통해 데이터 변경 및 API 처리 기능을 프레임워크 내부에서 구현할 수 있다.
      - 이미지 최적화, 폰트 최적화, SEO 메타데이터 관리, 파일 기반 라우팅 등의 기능도 제공한다.
      - 따라서 Next.js는 라우팅을 넘어 프론트엔드와 서버 기능, 렌더링, 최적화, 배포 구조까지 통합적으로 지원하는 프레임워크이다.
  - 고객 대상 서비스와 사내 서비스 등 상황이 달라져도 Next.js가 항상 가장 좋은 선택일까요?
    - Next.js가 항상 가장 좋은 선택은 아니며, 서비스의 목적, 사용자 환경, 개발 및 운영 복잡도 등을 고려하여 선택해야 한다.
    - 고객 대상 서비스는 검색 엔진 노출, 초기 로딩 속도, 다양한 사용자 환경 대응이 중요할 수 있으므로 Next.js가 적합할 수 있다.
    - 반면 사내 관리 시스템이나 대시보드처럼 로그인 이후 사용하며 상호작용이 중심인 서비스는 React와 Vite 기반 SPA로도 충분할 수 있다.
    - Next.js는 서버 기능과 렌더링 구조까지 제공하므로 프로젝트에 따라 설정 및 운영 복잡도가 증가하거나 제공 기능을 충분히 활용하지 못할 수 있다.
    - 반대로 사내 서비스라도 초기 로딩 성능, 서버 렌더링, 서버 기능 통합 등이 필요하다면 Next.js가 적합할 수 있다.
    - 결국 프레임워크 자체의 기능이나 인지도보다 서비스 요구사항, 팀의 기술 숙련도, 유지보수 비용을 기준으로 선택하는 것이 중요하다.
- Server Component와 Client Component
  - 어떤 기준으로 Server Component와 Client Component를 나누면 좋을까요?
    - Server Component는 서버에서 데이터를 가져오거나 정적인 UI를 렌더링하고, 서버 환경에서 처리해야 하는 로직을 수행하는 데 적합하다.
    - Client Component는 사용자 이벤트 처리, 상태 관리(`useState`), 생명주기 관리(`useEffect`), 브라우저 API 접근 등 상호작용이 필요한 기능을 담당하는 데 적합하다.
    - 데이터 조회, DB 접근, 비밀키 사용, 정적인 화면 구성 등은 Server Component로 처리하여 클라이언트에 전달되는 JavaScript 양을 줄이는 것이 좋다.
    - 버튼 클릭, 입력값 관리, 모달 제어, 실시간 UI 업데이트 등 사용자 상호작용이 필요한 부분은 Client Component로 분리하는 것이 좋다.
    - 기본적으로 Server Component를 사용하고, 클라이언트 기능이 필요한 부분만 Client Component로 최소화하여 구성하는 것을 권장한다.
  - `"use client";` 지시어를 `page.tsx` 최상단에 선언해도 될까요?
    - 기술적으로 `page.tsx` 최상단에 `"use client";`를 선언하는 것은 가능하며, 해당 페이지를 Client Component로 구성할 수 있다.
    - 하지만 `"use client"`를 선언하면 해당 파일을 기준으로 import되는 모듈들이 클라이언트 번들에 포함되는 클라이언트 경계가 형성된다.
    - 페이지 전체가 클라이언트 영역으로 확장되면 필요하지 않은 JavaScript까지 클라이언트에 전달되어 번들 크기와 hydration 부담이 증가할 수 있다.
    - 따라서 페이지 전체에 선언하기보다는 상태 관리, 이벤트 처리 등 클라이언트 기능이 필요한 컴포넌트에만 선언하는 것이 좋다.
    - 페이지의 데이터 조회나 서버 로직은 Server Component로 유지하고, 상호작용이 필요한 하위 컴포넌트만 Client Component로 분리할 수 있다.
- 렌더링 방식
  - `"use client";` 지시어가 붙은 Client Component는 브라우저에서만 렌더링될까요?
    - Client Component라고 해서 브라우저에서만 렌더링되는 것은 아니다.
    - Next.js에서는 초기 페이지 로드 시 Client Component도 서버에서 HTML을 미리 렌더링(Pre-rendering)할 수 있다.
    - 이후 브라우저에서 JavaScript를 실행하고 Hydration 과정을 거쳐 이벤트 처리와 상태 관리 등 상호작용이 가능해진다.
    - `"use client"`는 컴포넌트가 브라우저에서만 실행된다는 의미가 아니라, 클라이언트 측 기능을 사용할 수 있도록 클라이언트 컴포넌트 경계를 지정하는 지시어이다.
    - 다만 이후 페이지 이동 등 클라이언트 측 네비게이션에서는 서버가 생성한 RSC Payload를 활용해 화면을 갱신하는 방식으로 동작할 수 있다.
    - 따라서 Client Component도 서버 렌더링에 참여할 수 있으며, 서버에서 실행되는 초기 렌더링과 브라우저에서 실행되는 Hydration을 구분해야 한다.
  - SSR과 SSG를 더 정리해 보고, ISR과 ISSG가 각각 어떤 의미로 쓰이는지 조사해 보세요. 페이지 생성 시점과 렌더링 방식을 기준으로 서로 어떤 관계가 있는지도 살펴보세요.
    #### **① SSR (Server-Side Rendering)**
    - SSR은 사용자가 페이지를 요청할 때 서버에서 데이터를 가져오고 HTML을 렌더링하여 전달하는 방식이다.
    - 페이지가 요청되는 시점에 렌더링되므로 최신 데이터나 사용자별 데이터를 반영하기 적합하다.
    - 요청마다 서버 렌더링이 수행될 수 있어 서버 리소스 사용량이 증가할 수 있다.
    #### **② SSG (Static Site Generation)**
    - SSG는 빌드 시점에 페이지를 미리 생성하여 HTML 파일로 저장하는 방식이다.
    - 사용자가 페이지를 요청하면 미리 생성된 HTML을 전달하므로 응답 속도가 빠르고 서버의 렌더링 부담이 적다.
    - 빌드 시점에 생성된 콘텐츠를 제공하므로 데이터가 변경되어도 재생성하지 않으면 기존 콘텐츠가 유지된다.
    #### **③ ISR (Incremental Static Regeneration)**
    - ISR은 SSG의 정적 생성 방식에 재생성 기능을 추가한 방식이다.
    - 페이지를 미리 생성하여 정적으로 제공하면서 설정한 시간이나 특정 조건에 따라 페이지를 다시 생성할 수 있다.
    - 매 요청마다 페이지를 렌더링하지 않으면서 콘텐츠를 갱신할 수 있어 성능과 데이터 최신성을 함께 확보할 수 있다.
    #### **④ ISSG (Incremental Static Site Generation)**
    - ISSG는 일반적으로 Incremental Static Site Generation을 의미하며, 정적 페이지를 점진적으로 생성하거나 갱신하는 개념을 가리킨다.
    - Next.js에서는 이러한 점진적 정적 생성 기능을 주로 ISR(Incremental Static Regeneration)이라는 명칭으로 설명한다.
    - 따라서 Next.js를 학습할 때 ISSG를 별도의 독립적인 렌더링 방식으로 보기보다는 ISR과 연결된 개념으로 이해하는 것이 적절하다.
    ***
    - SSR과 SSG는 페이지를 생성하는 시점을 기준으로 구분할 수 있다.
    - SSR은 요청 시점에 생성하고 SSG는 빌드 시점에 생성한다.
    - ISR은 SSG를 기반으로 재생성 기능을 추가하여 정적 페이지의 갱신을 지원한다.
    - Next.js에서는 렌더링 방식뿐 아니라 데이터 캐싱과 재검증 설정에 따라서도 동작이 달라질 수 있으므로, 렌더링과 캐싱을 완전히 동일한 개념으로 이해하면 안 된다.
