- 프레임워크의 역할

  프레임워크 : 프로그래밍에서 특정 운영 체제를 위한 응용 프로그램 표준 구조를 구현하는 클래스와 라이브러리 모임

  → 프레임(틀, 규칙) + Work(일, 소프트웨어의 목적)

  → 목적에 따라 효율적으로 구조를 짜는 개발 방식

  Next.js :  풀스택 웹 애플리케이션을 구축하기 위한 React 프레임워크

  서버 사이드 렌더링(SSR) : 각 요청에 대해 서버에서 HTML 페이지를 생성, 초기 렌더링에 필요한 모든 데이터와 마크업 포함 가능

  정적 사이트 생성(SSG) : HTML 페이지가 빌드 시간에 생성, 정적 에셋으로 제공 → 각 요청마다 서버 사이드 렌더링이 필요하지 않게 된다.

    - Next.js는 TanStack Router에 더해 어떤 기능을 제공하나요?

      React Server Components, SSR, SSG, ISR 렌더링

      다층 캐싱

      내장 이미지,폰트 최적화 등의 풀스택 웹 프레임워크 기능

    - 고객 대상 서비스와 사내 서비스 등 상황이 달라져도 Next.js가 항상 가장 좋은 선택일까요?

      Next.js가 좋은 경우 → 고객 대상 서비스 일 때

        - 검색 엔진 최적화가 필수일 때
        - 초기 로딩 속도가 중요할 때
        - 풀스택 기능이 가볍게 필요할 때

      아닌 경우 → 사내 서비스

        - SEO가 전혀 필요 없을 때
        - 복잡한 클라이언트 상태 관리와 인터랙션이 많을 때
        - 인프라 및 유지보수 비용 절감이 필요할 때

- Server Component와 Client Component

  Server Component : 서버에서만 실행되는 React 컴포넌트

  → 번들 크기 줄임, 초기 로딩 속도 향상, 보안

  데이터 페칭

  인증

  비즈니스 로직 등 서버에서 처리해야 할 작업을 효율적으로 수행

  Client Component : 사전 렌더링(prerendered)된 인터랙티브한 사용자 인터페이스(UI)를 작성할 수 있게 해준다.

  장점

    - 인터랙티비티(Interactivity): 클라이언트 컴포넌트는 상태, 효과, 이벤트 리스너를 사용할 수 있어 사용자에게 즉각적인 피드백을 제공하고 UI를 업데이트 가능
    - 브라우저 API 접근 : 클라이언트 컴포넌트는 지리 위치나 로컬 스토리지와 같은 브라우저 API에 접근 가능
    - 어떤 기준으로 Server Component와 Client Component를 나누면 좋을까요?

      상호작용이 필요한 곳만 Client Component로 분리

      사용자 상호작용

      상태, 생명주기

      나머지는 기본값인 Server Component로 유지

      데이터 조회, 민감한 정보 보호, 번들 크기 절감

    - `"use client";` 지시어를 `page.tsx` 최상단에 선언해도 될까요?

      use client;를 page.tsx 에 선언해도 되지만 페이지 전체를 Client Component로 만들 필요가 없다면 Server Component로 유지하고 상호작용이 필요한 최소 범위만 Client Component로 분리하는게 좋다.

- 렌더링 방식

  서버 컴포넌트에서 렌더링

    - 동적 렌더링 : 각 사용자 요청 시점에 라우트를 렌더링
    - 정적 렌더링 : 페이지를 빌드 시점에 미리 생성하거나 데이터 재검증 후 백그라운드에서 렌더링
    - 스트리밍 : 라우트 세그먼트 병렬화, 부분 렌더링 및 로딩 UI

  보안, 캐싱, 성능에 좋다

  클라이언트 컴포넌트에서 렌더링

  전체 페이지/ 이후 네비게이션 다르게 렌더링

  전체 페이지

  서버 → RSC payload로 렌더링,

  클라이언트 → 서버에서 렌더링된 HTML을 사용하여 빠른 비인터랙티브 초기 미리보기를 즉시 표시

  이후 네비게이션

  클라이언트 컴포넌트가 완전히 클라이언트에서 렌더링

    - `"use client";` 지시어가 붙은 Client Component는 브라우저에서만 렌더링될까요?

      초기 렌더링 시 서버에서도 한 번 렌더링된 후 브라우저에서 하이드레이션 및 클라이언트 측 리렌더링

      하이드레이션 : 정적 HTML에 이벤트 리스너를 연결하여 인터랙티브하게 만드는 과정

    - SSR과 SSG를 더 정리해 보고, ISR과 ISSG가 각각 어떤 의미로 쓰이는지 조사해 보세요. 페이지 생성 시점과 렌더링 방식을 기준으로 서로 어떤 관계가 있는지도 살펴보세요.

      SSR : 사용자가 페이지를 요청할 때마다 서버가 실시간으로 데이터를 조회해 HTML을 생성하여 응답하는 방식

      SSG (Static Site Generation) : 빌드 시점에 미리 모든 페이지의 HTML을 정적 파일로 생성해 두고 요청이 오면 저장된 HTML을 즉시 반환

      ISR : SSG로 생성된 정적 페이지를 전체 재빌드 없이 설정한 주기(예: 60초)나 특정 이벤트(On-demand)에 따라 백그라운드에서 개별적으로 재생성하는 방식

      ISSG : ISR과 사실상 같은 의미, 빌드 시점에 모든 페이지를 만들지 않고, 최초 요청 시 점진적으로 정적 페이지를 생성해 나가는 방식
